## ปัญหาที่โปรเจกต์นี้มีอยู่เพื่อตอบ

ไฟจราจรที่สี่แยกหนึ่งตัดสินใจปล่อยรถออกไป แต่ถนนข้างหน้าอาจรับรถไม่ไหว ถ้าเป็นแบบนั้น
รถจะไปค้างขวางทางแยกถัดไป (เรียกว่า **spillback**) แล้วรถติดลามย้อนไปทั้งโครงข่าย
คำถามที่ CADENCE ต้องการตอบคือ:

> **ถ้าแยกนี้ปล่อยรถชุดนี้ออกไปตอนนี้ โครงข่ายรอบ ๆ จะเกิดอะไรขึ้น?**

โปรเจกต์ปี 2020 เคยถามคำถามนี้แล้วตอบไม่ได้ โดยใช้ RL บน SUMO แต่ simulator ไม่เคยถูก
ตรวจว่าเชื่อถือได้ พอผลออกมาไม่ดี เช่นเกิด deadlock ในโครงข่ายใหญ่ ก็แยกไม่ออกว่าตัวควบคุมผิด
หรือสภาพแวดล้อมผิด บทเรียนหลักคือ **อย่า optimise สภาพแวดล้อมที่เรายังไม่ไว้ใจ**
(`AP-01`) CADENCE จึงสร้างเครื่องมือวัดก่อน แล้วค่อยใส่ตัวควบคุมทีหลัง

## ใครเกี่ยวข้อง และข้อมูลไหลยังไง

| ผู้เล่น | บทบาท |
|---|---|
| **SUMO** | simulator จราจรระดับรถทีละคัน ทำหน้าที่เป็น "โลกจริง" ของการทดลอง |
| **แพลตฟอร์ม (Zone A)** | อ่านสถานะจาก SUMO แปลงเป็นสถานะกลางที่ไม่ผูกกับ SUMO, รับคำขอจากตัวควบคุม, เปลี่ยนไฟอย่างปลอดภัย และบันทึกทุกอย่างลงโฟลเดอร์ผลลัพธ์ |
| **ตัวควบคุม** | fixed-time, SUMO actuated, RL (PPO/DQN), Max-Pressure ทุกตัวแข่งบนสัญญาเดียวกัน |
| **การศึกษา (Zone B)** | ชุดการทดลองที่อ่านโฟลเดอร์ผลลัพธ์แล้วเทียบตัวควบคุมกัน |
| **ผู้วิจัย** | ตั้งคำถาม ตัดสินใจ และเป็นคนสรุปผลการศึกษา |

```
scenario ─► SUMO ─► สถานะกลาง ─► ตัวควบคุม ─► "ขอเปลี่ยนเป็น phase B"
                                                         │
SUMO ◄── ไฟเปลี่ยนจริง ◄── safety layer (เหลือง, min green ฯลฯ) ◄┘
  │
  └─► โฟลเดอร์ผลลัพธ์ ─► metrics ─► เทียบตัวควบคุม
```

ตัวควบคุมไม่เคยสั่ง SUMO ตรง ๆ มัน **ขอ** เปลี่ยน phase แล้ว safety layer เป็นคนเลือกว่าจะ
เปลี่ยนอย่างถูกกฎยังไง (`ARCH-D04`)

**ตัวอย่างจากข้อมูลจริง:** scenario `s0_turning` เป็นสี่แยกเดียวชื่อ `A0` มีสอง stage ที่ให้
ไฟเขียว (stage 0 และ 2) ตามโปรแกรมเดิมของ SUMO แต่ละ stage เขียว 42 วินาที คั่นด้วยไฟเหลือง
3 วินาที ส่วน `signal_plan.yaml` กำหนดว่าตัวควบคุมจะเปลี่ยนไฟได้หลังเขียวมาแล้วอย่างน้อย
10 วินาที และต้องเปลี่ยนเมื่อเขียวถึง 60 วินาที ถ้าตัวควบคุมขอ stage 2 ตอนวินาทีที่ 20
safety layer ต้องจ่ายไฟเหลืองครบ 3 วินาทีก่อนเข้า stage 2 เสมอ ไม่มีทางลัด

## ปลายทาง

**Study 1** (M9): ทดสอบว่า RL ที่มองเห็นโครงข่ายชนะ Max-Pressure ได้หรือไม่ ในสภาพรถเกิน
ความจุและในสภาพ spillback บนถนนช่วงหนึ่งที่มีไฟ 3–5 แยก ซึ่งสร้างจากแผนที่จริง ผลจะน่าเชื่อถือ
ได้ก็ต่อเมื่อครบสามอย่าง:
- simulator ที่ตรวจแล้วว่าเชื่อถือได้
- baseline ที่แข็งพอ ชนะมันแล้วมีความหมาย
- สัญญาตัวควบคุมที่ให้ทุกวิธีแข่งกันอย่างเท่าเทียม

## สิ่งที่จะไม่ทำ

ไม่ทำ simulation ระดับเมือง, ไม่ให้ LLM ควบคุมไฟจราจร, ไม่ทำ MARL หรือ GNN, ไม่เชื่อมระบบจริง
และไม่ deploy จริง LLM ช่วยได้แค่ฝั่ง workflow การวิจัย ไม่ใช่ตัวตัดสินใจเรื่องไฟ
(`DIRECTION.md` §9)

## ทำไปถึงไหนแล้ว (ระดับ milestone)

- **M0–M1 เสร็จแล้ว:** SUMO รันแบบ deterministic ได้, มีสถานะกลาง และมี metric registry
- **ตอนนี้อยู่ M2:** สร้าง safety layer และสัญญาตัวควบคุม ส่วนที่เสร็จแล้วคือ signal plan และ
  executor ที่ยังไม่ต่อกับ SUMO
- รายละเอียดของแต่ละ phase อยู่ในหัวข้อถัดไป ส่วนสถานะของแต่ละ ticket ดูได้จาก GitHub
  milestone ของ phase นั้น

## Phase และ gate

เลข phase ตรงกับเลข milestone: P2 คือ M2 และไล่ไปจนถึง P9 คือ M9 gate คือคำถามเชิงธุรกิจที่ต้องตอบ
ด้วยหลักฐาน ไม่ใช่ด่านอนุมัติ

| phase | เป้าหมาย | gate ถามว่า |
|---|---|---|
| **P2** Signal Safety + Controller Contract | ตัวควบคุมสั่งไฟได้ผ่านสัญญาเดียว และ safety layer เป็นคนคุมทุกการเปลี่ยนไฟ | **G2** ตัวควบคุมที่ลอกโปรแกรมเดิมของ SUMO ทำงานผ่านสัญญาแล้วได้ผลตรงกับการรันแบบไม่มีตัวควบคุมทุกไบต์หรือไม่ ถ้าไม่ตรง แปลว่ายังขาดกฎการเปลี่ยนไฟบางข้อ |
| **P3** Validation Controllers | fixed-time ที่จูนแล้ว และ actuated ของ SUMO วิ่งผ่านสัญญา | **G3** fixed-time ไม่ได้อ่อนเกินจริง และ actuated ตอบสนองต่อ demand จริงหรือไม่ ถ้าไม่ใช่ การเทียบใน P6 จะไม่มีความหมาย |
| **P4** RL Adapter | เปิดสัญญาให้ RL ใช้ผ่าน Gymnasium | — |
| **P5** PPO (+ DQN) | ระบบ train และ evaluate ที่รันหลาย seed ได้ | — |
| **P6** Single-Intersection Experiments | เทียบ fixed-time, actuated และ RL บนแยกจำลอง | **G6** RL ชนะ baseline ตอนรถเกินความจุหรือไม่ ถ้าไม่ชนะ ต้องทบทวน observation และ reward ก่อนไปแยกจริง |
| **P7** Real-World Intersection | แยกจริงจาก OSM ที่ผ่านการ validate | **G7** แยกจริงตรงกับข้อมูลที่สังเกตได้หรือไม่ ถ้าไม่ตรง ต้องเลือกแหล่งข้อมูลใหม่ (`PD-Q01`) |
| **P8** Corridor + Max-Pressure | ถนนช่วงหนึ่งที่มีไฟ 3–5 แยก, ตัววัด spillback และ Max-Pressure | — |
| **P9** Network-Aware RL vs Max-Pressure | Study 1 | **G9** RL ที่มองเห็นโครงข่ายชนะ Max-Pressure ตอนรถเกินความจุและตอนเกิด spillback หรือไม่ ไม่ว่าคำตอบจะออกมาทางไหนก็คือผลของ Study 1 |
